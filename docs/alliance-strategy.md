> ⚠️ **내부 전략 문서** — 외부 공개 불가

## 1. 트래블룰 솔루션 연동 구조 팩트 정리

### 1.1 CODE VASP (오픈형) — Sumsub 경유 연동

| 항목 | 실제 상황 |
|------|-----------|
| **네트워크 유형** | 오픈형. 빗썸·코인원·코빗이 설립한 국내 TR 솔루션 |
| **Sumsub과 프로토콜 연동** | ✅ 완료. Sumsub이 CODE API와 직접 통합 |
| **Sumsub 경유 시 CODE 직접 가입 필요?** | ❌ 불필요. CODE에 별도 회원가입 불필요 |
| **절차** | Sumsub 내에서 CODE 네트워크 이용을 위한 Registration Form / DD Questionnaire 작성 필요 (Sumsub CSM 통해 진행) |
| **허들** | CODE 직접 가입 대비 **대폭 간소화**. Sumsub이 vetting 대행 |
| **과금** | Sumsub API 호출 기반 과금. CODE 측 별도 비용은 Sumsub-CODE 계약에 포함 |

**요약**: Sumsub 플랫폼에 엔티티 등록 + 간소 DD만 통과하면, CODE 네트워크에 있는 모든 거래소(업비트·빗썸·코인원 등)와 TR 메시지 교환이 즉시 가능하다. 기술 연동은 Sumsub이 전담.

### 1.2 VerifyVASP (폐쇄형) — 근본적으로 다른 구조

| 항목 | 실제 상황 |
|------|-----------|
| **네트워크 유형** | 폐쇄형(Closed Network). 자체 프로토콜 + On-premises Enclave Server 설치 요구 |
| **Sumsub/Notabene 경유 가능?** | ⚠️ 사실상 불가. 프로토콜 레벨 자동 라우팅 안 됨 |
| **연동 방법** | Alliance 간 **Bilateral Agreement** 체결 필수. 기술적 협의 + 법적 합의 + DD 심사 선행 |
| **가입 절차** | VerifyVASP 자체 엄격 DD → API Key 발급 → Enclave Server 설치 → IP 화이트리스트 등록 |
| **현재 추세** | Sygna 인수 등 네트워크 흡수·통합 전략. 외부 연동보다 자체 확장 지향 |

**요약**: Sumsub이든 Notabene이든 경유한다고 해서 자동 연결되지 않는다. 솔루션 대 솔루션 수준의 별도 협정이 없으면 기술적으로 불가.

### 1.3 비교 요약

```
                        CODE VASP (오픈형)              VerifyVASP (폐쇄형)
                     ─────────────────────          ─────────────────────
Sumsub 경유 가능?     ✅ 가능                        ❌ 사실상 불가
                     (Sumsub 내 간소 DD만)            (별도 Alliance DD + 
                                                     Bilateral Agreement 필요)

TranSight 고객의      Sumsub 브릿지 타고              VerifyVASP와 별도 계약 +
연동 허들             자동 라우팅 → 낮음              기술 연동 필요 → 높음

우리 대응              Phase 1에서 즉시 활용           Phase 3 이후 협상력 확보 후
                                                     Alliance 레벨 협의
```

## 2. 핵심 전제: TranSight KYT 기존 고객 기반

> 🔑 **이 전략의 전체 기반은 아래 사실에 있다.**

### 2.1 TranSight의 현재 포지션

TranSight는 현재 **한국 유일의 KYT(Know Your Transaction) 솔루션**을 운영하고 있으며, 이미 아래 기관들이 TranSight KYT를 사용 혹은 사용 예정 중이다:

| 구분 | 기관 | 비고 |
|------|------|------|
| 거래소 | **업비트** | 국내 최대 가상자산 거래소 |
| 은행 | **신한은행** | 시중은행 |
| 은행 | **국민은행** | 시중은행 |
| 은행 | **하나은행** | 시중은행 |
| 인터넷전문은행 | **카카오뱅크** | 인터넷전문은행 |
| 인터넷전문은행 | **케이뱅크** | 인터넷전문은행 |
| 핀테크 | **카카오페이** | 간편결제/송금 |
| 핀테크 | **토스** | 간편결제/송금 |

**이 기관들은 TranSight와 이미 계약 관계에 있고, 기술 연동이 완료되어 있으며, 신뢰 관계가 구축되어 있다.** 이것이 TTR(TranSight TR) 전략의 출발점이다.

### 2.2 전략적 의미

이 고객 기반의 존재는 TTR 전략의 성격 자체를 바꾼다:

| 일반적인 신규 TR 솔루션 | TranSight TR |
|--------------------------|-------------|
| Cold Start: 고객 0에서 시작 | **Warm Start**: 8개 기관이 이미 TranSight 고객 |
| "가입해도 쓸 상대가 없다" 문제 | Sumsub 브릿지 + **기존 고객 관계** 즉시 활용 |
| 신규 영업: 관계 구축부터 시작 | **크로스셀**: 기존 KYT 계약 위에 TR 얹기 |
| 영업 사이클: 12~18개월 | **단축 가능**: 이미 의사결정권자와 관계 있음 |
| 기술 연동: 처음부터 | **확장 연동**: 기존 KYT 인프라에 TR 모듈 추가 |

## 3. TranSight TR 얼라이언스 성장 전략 (수정)

### 3.1 전략 개요

TTR의 핵심 전략은 **"KYT 기존 고객에게 TR을 번들 크로스셀 → CODE VASP 대체 → 네트워크 효과로 얼라이언스 역전"**이다.

```
┌─────────────────────────────────────────────────────────┐
│  고객 피칭 핵심 메시지                                     │
│                                                         │
│  "CODE VASP 따로 쓸 필요 없습니다.                         │
│   TTR 쓰시면 TR은 거의 원가에 드리고,                       │
│   어차피 쓰고 계신 KYT랑 한번에 묶여서 관리됩니다.             │
│   CODE 커버 범위(국내 거래소)는 저희가 다 가져갑니다."         │
└─────────────────────────────────────────────────────────┘
```

### 3.2 번들 가치 제안 (Bundle Value Proposition)

#### 고객 입장 비용 비교

```
[현재: 분리 운영]                    [TTR 전환 후: 통합 운영]
                                    
┌──── KYT ────┐  ┌── TR (CODE) ──┐   ┌──── KYT + TR (TTR) ────┐
│ TranSight   │  │ CODE VASP    │   │ TranSight 통합 플랫폼    │
│ KYT 비용    │  │ 별도 가입비   │   │                         │
│             │  │ 건당 과금     │   │ KYT 기존 비용            │
│             │  │ 별도 연동 관리│   │ + TR 원가 수준 추가      │
└─────────────┘  └──────────────┘   │ = 거의 CODE 단독 가격    │
                                    │                         │
 2개 벤더, 2개 계약, 2개 연동          │ 1개 벤더, 1개 계약,      │
                                    │ 1개 통합 대시보드         │
                                    └─────────────────────────┘
```

#### 고객별 피칭 시나리오

| 고객 | 현재 상태 | TTR 피칭 포인트 |
|------|-----------|----------------|
| **업비트** | KYT=TranSight, TR=CODE VASP | "CODE 비용을 TTR로 대체. KYT+TR 통합 관리. CODE 커버리지 Sumsub 경유로 동일하게 유지" |
| **신한은행** | KYT=TranSight, TR=미도입(또는 검토 중) | "TR 의무화 대비. 기존 KYT 연동에 TR 모듈만 추가. 전용선/VPN 맞춤 연동" |
| **카카오페이** | KYT=TranSight, TR=미도입 | "CODE 직접 가입 불필요. TTR 하나로 국내 거래소 전체 커버. 원가 수준 제공" |
| **토스** | KYT=TranSight, TR=미도입 | 카카오페이와 동일 논리 |
| **카카오뱅크/케이뱅크** | KYT=TranSight, TR=미도입 | "인터넷전문은행 맞춤 mTLS 보안 채널 제공. CODE/VerifyVASP 못하는 영역" |

### 3.3 Phase별 로드맵 (수정)

#### Phase 1: KYT 고객 크로스셀 (Day 1 ~ 6개월)

```
기존 TranSight KYT 고객 (8개 기관)
       │ "TR도 우리 거 쓰세요. 원가에 드립니다."
       ▼
  TranSight TR Hub
       │
       ▼ (Sumsub Adapter)
  Sumsub Hub (TRUST)  ←── CODE 커버리지 확보
       │
       ├──▶ CODE VASP 거래소들
       └──▶ TRUST 글로벌 VASP
```

- **목표**: 기존 KYT 고객 8곳 중 **최소 3~4곳을 TTR 고객으로 전환**
- **핵심 무기**: 
  - 이미 구축된 관계 + 기술 연동 기반 → 영업 사이클 대폭 단축
  - TR 원가 제공 → CODE VASP 대비 가격 경쟁력 압도
  - KYT+TR 통합 운영 → 벤더 수 감소, 관리 효율 향상
- **수익 모델**: TR 자체는 원가 수준. **KYT 계약 유지·강화가 진짜 수익원** (TR은 lock-in 도구)
- **Sumsub 의존도**: 🔴 높음 (외부 연동 전량 Sumsub 경유)
- **KYT 고객 전환에 실패할 리스크**: 🟢 낮음 (가격 + 관계 + 기술 호환성 모두 우위)

#### Phase 2: 자체 얼라이언스 공고화 (6개월 ~ 12개월)

```
         ┌── 업비트 (거래소·KYT+TR) ─────┐
         ├── 신한은행 (은행·KYT+TR) ──────┤
         ├── 카카오페이 (핀테크·KYT+TR) ──┤
         ├── 토스 (핀테크·KYT+TR) ────────┤
         ├── 국민은행 (은행·KYT+TR) ──────┤
         └── 카카오뱅크 (인뱅·KYT+TR) ────┘
                       │
                  TranSight Alliance
                       │
          ┌────────────┼────────────┐
          ▼            ▼            ▼
     자체 직접 라우팅   Sumsub경유    미래 연동
     (멤버 간 즉시)    (CODE/TRUST)  (VerifyVASP)
```

- **상황**: TTR 고객이 4곳 이상이면, **이미 자체 얼라이언스 멤버 간 직접 라우팅이 의미 있는 규모**
  - 예: 카카오페이 → 업비트 (TranSight 내부 직접 라우팅, Sumsub 불필요, 지연시간 ~0ms)
- **전환점**: "신한은행이랑 TR 하려면 TTR 써야 한다" → CODE/VerifyVASP 거래소들에게 TTR 가입 유인 발생
- **Sumsub 의존도**: 🟡 중간 → 점진 감소

#### Phase 3: 네트워크 효과 발동 → 얼라이언스 역전 (12개월~)

```
                TranSight Alliance
                ┌────────┴────────┐
     ┌──────────┴──────────┐      │
     │  기존 KYT+TR 고객    │      │
     │  (금융기관·거래소)    │      │
     └──────────┬──────────┘      │
                │                 │
     ┌──────────▼──────────┐      │
     │  CODE/VV 거래소들    │◀─────┘ 자발적 합류
     │  (금융기관과 TR 필요) │        "금융기관이 여기 있으니까"
     └─────────────────────┘
```

- **메커니즘**: 한국의 주요 은행·핀테크가 전부 TranSight에 있으면, CODE/VerifyVASP 거래소들은 **금융기관과 가상자산 거래를 하려면 TranSight 얼라이언스에 들어올 수밖에 없음**
- **CODE 거래소**: Sumsub 경유로 이미 연결되어 있지만, 직접 TTR 가입 시 수수료 절감 + 저지연 인센티브
- **VerifyVASP 거래소**: 이 시점에서 TranSight 협상력 확보 → Bilateral Agreement 체결 가능
- **Sumsub 의존도**: 🟢 낮음 (자체 직접 라우팅이 주력, Sumsub은 글로벌 fallback 용도만)

## 4. 전략 분석 및 의견

### 4.1 이 전략이 극도로 강력한 이유

**1. Cold Start가 아니라 Warm Cross-sell이다**

이전 분석에서 "Sumsub으로 cold start를 우회한다"고 했는데, 실제로는 cold start 자체가 존재하지 않는다. **이미 8개 기관이 TranSight 고객이다.** 이건 "새로운 플랫폼을 처음 시작하는 것"이 아니라 **"기존 제품 위에 기능을 하나 더 얹는 것"**에 가깝다. 영업 난이도가 완전히 다르다.

**2. "TR 원가 제공"이 가능한 이유가 있다**

보통 원가에 뿌리면 사업이 안 되지만, TranSight의 경우 **TR은 미끼고 KYT가 본체**다. TR을 원가에 제공해도:
- KYT 계약이 더 견고해진다 (경쟁사로 이탈 방지)
- KYT+TR 통합으로 교체 비용(switching cost)이 올라간다
- 향후 TR 물량이 커지면 마진을 자연스럽게 붙일 수 있다

이건 **프린터 회사가 프린터를 싸게 팔고 잉크로 버는 구조**와 본질적으로 같다. TR이 프린터고, KYT가 잉크다.

**3. CODE VASP를 직접 공격하지 않으면서 대체한다**

이 전략의 우아한 점은 CODE VASP와 **정면 경쟁을 선언하지 않는다**는 것이다:
- CODE 커버 범위를 Sumsub 경유로 그대로 가져가므로, CODE 입장에서는 메시지가 여전히 자기 네트워크를 통과한다
- CODE의 고객(거래소)을 빼앗는 게 아니라, CODE의 고객과 연결되는 **금융기관 측 진입점**을 장악하는 것
- CODE 입장에서 당장 적대적으로 느낄 이유가 적다 (오히려 금융기관과의 TR 볼륨이 늘어나는 셈)

**4. 비대칭 브릿지가 "선택이 아닌 필수"가 된다**

업비트가 카카오페이와 TR을 해야 하는 상황에서:
- CODE VASP: 카카오페이가 CODE에 가입해야 함 → 카카오페이 보안 정책과 충돌 가능
- TTR: TranSight가 카카오페이 보안 요구에 맞춰 mTLS/VPN/전용선으로 연결해 줌 → 이게 비대칭 브릿지의 존재 이유

**금융기관은 자기들 보안 기준을 낮출 이유가 없다.** 따라서 금융기관이 원하는 방식에 맞추는 TranSight이 유일한 선택지가 된다.

### 4.2 리스크 재평가 (KYT 고객 기반 반영)

| 리스크 | 심각도 | 재평가 근거 |
|--------|--------|-------------|
| **Sumsub 가격 인상** | 🟡 중간 (하향) | Sumsub 관계 협상 가능 + 자체 얼라이언스가 빠르게 형성되면 의존도 빠르게 감소 |
| **금융기관 영업 사이클** | 🟢 낮음 (하향) | **이미 고객이다.** 계약 어멘드먼트 or 추가 모듈 도입 수준. 12~18개월 → 3~6개월로 단축 가능 |
| **VerifyVASP 금융기관 선제 영업** | 🟡 중간 (유지) | 위험은 존재하지만, TranSight KYT로 이미 관계가 있으므로 first-mover advantage 확보 |
| **CODE VASP 반발** | 🟢 낮음 (하향) | 정면 경쟁이 아닌 보완적 구조. CODE에도 금융기관 트래픽이 늘어나는 이점 |
| **자금 흐름** | ✅ 해소 | 자원 충분 확인 |

### 4.3 추가 전략 제안

**1. "KYT+TR 통합 대시보드"를 킬러 피처로**

금융기관 컴플라이언스 담당자 입장에서 KYT와 TR이 한 화면에서 관리되는 건 엄청난 가치다:
- 특정 거래의 KYT 판정 결과 → TR 메시지 전달 여부 → 최종 상태까지 **하나의 타임라인**으로 추적
- 이건 CODE+별도KYT 조합으로는 절대 못 만드는 UX
- 이 통합 경험이 switching cost를 극도로 높인다

**2. 업비트를 첫 번째 전환 타겟으로**

업비트는 현재 KYT=TranSight, TR=CODE VASP를 쓰고 있을 가능성이 높다. 업비트가 TTR로 전환하면:
- 국내 최대 거래소가 TTR 레퍼런스 → 나머지 기관 전환 도미노
- 업비트 입장에서: KYT+TR 통합 관리 + 비용 절감 인센티브
- 다만 업비트는 CODE 설립 멤버(빗썸·코인원·코빗)가 아니므로 CODE 이탈에 대한 정치적 부담이 상대적으로 적음

**3. Sumsub과의 관계를 "한국 금융기관 채널 파트너"로 프레이밍**

TranSight가 한국 금융기관들을 Sumsub 네트워크에 태워주는 구조이므로, Sumsub 입장에서 TranSight는 **한국 시장 채널 파트너**다. 이 프레이밍을 명시적으로 공유하면 win-win 관계를 견고히 유지할 수 있다.

**4. 자체 CODE 직접 연동을 보험으로 확보**

현재 코드베이스의 `CodeVaspAdapter`를 실제 CODE API에 직접 연결 가능한 상태로 만들어 두면, Sumsub 경유 없이도 CODE 네트워크에 접근 가능한 보험이 된다. CODE는 오픈형이므로 TranSight 자체의 CODE 직접 가입도 가능하다.

## 5. 전략 요약

```
┌─────────────────────────────────────────────────────────────────┐
│                    TranSight TR 전략 한 줄 요약                    │
│                                                                 │
│  "KYT 기존 고객에게 TR을 원가로 번들 → CODE VASP 대체           │
│   → 금융기관 얼라이언스 형성 → 거래소 자발적 합류               │
│   → Sumsub 의존도 자연 감소 → 한국 TR 생태계 허브"              │
└─────────────────────────────────────────────────────────────────┘
```

| 항목 | 내용 |
|------|------|
| **핵심 자산** | TranSight KYT 기존 고객 8개 기관 (업비트, 신한, 국민, 하나, 카카오뱅크, 케이뱅크, 카카오페이, 토스) |
| **전략 유형** | Cold Start 우회가 아닌 **Warm Cross-sell + Bundle Pricing** |
| **Phase 1** | KYT 고객에 TR 크로스셀. TR 원가 제공. Sumsub 경유 CODE 커버리지 확보 |
| **Phase 2** | 자체 얼라이언스 공고화. 멤버 간 직접 라우팅. 금융기관 맞춤 보안 채널 |
| **Phase 3** | 네트워크 효과 발동. CODE/VV 거래소 자발적 합류. Sumsub 의존도 자연 감소 |
| **핵심 무기** | ① KYT 기존 관계 ② TR 원가 번들 ③ 비대칭 브릿지 (금융기관 보안) ④ KYT+TR 통합 UX |
| **수익 구조** | TR=미끼(원가), KYT=본체(수익원). TR이 KYT lock-in을 강화하는 구조 |
| **경쟁 구도** | CODE와 정면 대결 ❌ → 보완적 포지셔닝으로 시작, 점진적 대체 |
| **최대 강점** | 이미 고객이 있다. 관계가 있다. 기술 연동이 되어 있다. |
| **최대 리스크** | VerifyVASP의 금융기관 선제 영업 (→ 속도로 대응) |
